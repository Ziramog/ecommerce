## 1. Resumen Ejecutivo

El hito **M360-050** completa la preparación arquitectónica y operativa para el despliegue definitivo de **Mercadal Digital 360** en el VPS Ubuntu 24.04 LTS (`mercadal-prod`), cumpliendo con la separación estricta entre Staging y Producción y asegurando la no interferencia con los servicios preexistentes de WOLFIM, Hermes y Tailscale.

Conforme a las reglas obligatorias del proyecto:
- **No se ejecutaron comandos remotos en el VPS ni se afectó el entorno productivo de WOLFIM**.
- Los artefactos quedan versionados y documentados en un runbook paso a paso listo para su ejecución controlada cuando el usuario lo autorice explícitamente.

## 2. Aislamiento Estricto y Matriz de Recursos (Staging vs Producción)

| Parámetro | Entorno Staging (`mercadal-staging`) | Entorno Producción (`mercadal-prod`) |
|---|---|---|
| **Namespace Docker** | `mercadal-staging` | `mercadal-prod` |
| **Política de Arranque** | `restart: "no"` (a demanda) | `restart: unless-stopped` |
| **Red Bridge Docker** | `mercadal_staging_net` | `mercadal_prod_net` |
| **Base de Datos** | `mercadal_staging_db` | `mercadal_prod_db` |
| **Volúmenes** | `mercadal_staging_*` | `mercadal_prod_*` |
| **Puerto Host Backend** | `100.124.132.48:9000` (Tailscale) | `127.0.0.1:9001` (Loopback interno Caddy) |
| **Puertos Públicos** | Cero puertos públicos | `80` y `443` (Caddy Reverse Proxy con SSL) |
| **Límite RAM Total** | < 1.8 GB RAM | < 3.2 GB RAM (con hard limits cgroups) |

## 3. Componentes Diseñados & Arquitectura

### 3.1 Orquestación Docker Compose (`docker-compose.prod.yml`)
- **`postgres` (PostgreSQL 16 Alpine)**: Memoria limitada a 512M, CPU 1.0, solo expuesto en la red interna `mercadal_prod_net`.
- **`redis` (Redis 7 Alpine)**: Memoria limitada a 256M, CPU 0.5, persistencia AOF activada y autenticación por contraseña.
- **`medusa-api` (Medusa 2.21.2)**: Memoria 1024M, CPU 1.5, vinculado al puerto `127.0.0.1:9001` (sin colisión con staging).
- **`pampa-novus` (Storefront B2C)**: Memoria 512M, CPU 1.0, puerto interno 3000.
- **`talabarteria-b2b` (Portal B2B)**: Memoria 512M, CPU 1.0, puerto interno 3001.
- **`caddy` (Caddy 2.8 Alpine)**: Memoria 128M, CPU 0.5, reverse proxy y terminación TLS automática.

### 3.2 Reverse Proxy & Hardening (`Caddyfile`)
- **Auto-HTTPS Let's Encrypt** para:
  - `pampanovus.com.ar` y `www.pampanovus.com.ar` (B2C).
  - `mayorista.talabarteriamercadal.com.ar` (B2B).
  - `api.mercadal.com.ar` (Medusa Store API).
- **Restricción Privada de Admin**:
  `admin.mercadal.com.ar` está protegido a nivel de proxy Caddy, permitiendo el acceso únicamente a peticiones provenientes de la red privada VPN de Tailscale (`100.64.0.0/10`) o localhost, bloqueando todo intento externo con HTTP 403 Forbidden.
- **Cabeceras de Seguridad**: HSTS (1 año), X-Content-Type-Options: nosniff, X-Frame-Options: SAMEORIGIN y remoción de cabecera Server.

### 3.3 Runbook de Despliegue y Respaldo (`README.md`)
- Procedimiento pre-flight no destructivo de puertos y memoria.
- Generación de secretos *in situ* con `openssl rand -hex`.
- Migraciones seguras con `medusa db:migrate`.
- Plan de contingencia con backups diarios cron de PostgreSQL y procedimiento de rollback inmediato ante incidentes.
